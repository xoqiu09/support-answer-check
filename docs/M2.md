# M2 模型接入与回答回放

## 先离线回放

在仓库根目录运行。回放按用例编号从已保存的回答 JSONL 取问答结果，并按用例文件的顺序写出。可以直接使用现有假客服的回答文件。

```sh
python3 -m answercheck run-bot --bot replay --recording data/answers/careful.jsonl \
  --kb data/kb --cases data/cases.jsonl --out /tmp/sac-replay.jsonl
```

如果记录漏了 `c01`，命令会报 `回放记录缺少用例 c01 的回答` 并以状态码 2 退出。JSON 或回答格式有问题时，报错会指明记录文件和行号。

## 以后怎么接真实模型

为想使用的 OpenAI 兼容服务设置以下环境变量。`OPENAI_BASE_URL` 填 API 基础地址，例如 `https://api.example.com/v1`，程序会追加 `/chat/completions`。`OPENAI_MODEL` 填服务商提供的模型名。`OPENAI_API_KEY` 填服务商发的密钥，把它保存在本机的环境里。

```sh
python3 -m answercheck run-bot --bot http \
  --kb data/kb --cases data/cases.jsonl --out /tmp/sac-http.jsonl
```

显式运行这条命令才会请求模型。每道题发一次请求，同次发送问题和全部知识库段落。服务商可能按输入和输出用量收费，跑整套 40 题前先检查价格。测试使用注入的传输函数，不联网。

拿到新的回答后，可以用原有 `validate` 和 `check` 命令评估。运行 `agree` 前，须针对这批新回答逐条重新做独立标注。即使用例相同，也不能沿用假客服的标签。

## 回复异常会怎样

- 环境变量有缺失或为空时，命令在发请求前列出缺少的变量名，以状态码 2 退出。
- 模型正文里的 `[doc#n]` 会与知识库核对。有效编号会写入 `citations`。不存在的编号会从正文和引用列表移除，终端输出带 `BAD_CITATION`、用例号和段落号的警告。没有引用的正文仍会记录，`citations` 为空。
- 需要转人工时，模型在正文之后另起一行写 `[转人工]`，并把这一行放在最后。程序用这一行将 `handoff` 标记为 `true`，写入文件时去掉标记。正文里写「无需转人工」时，`handoff` 为 `false`。
- HTTP 请求出错时，命令会报 `用例 c01 的模型请求失败`。如果回复正文或引用回显了当前 API 密钥，命令会报 `用例 c01 的模型回复包含 API 密钥，已拒绝`。这两种情况都以状态码 2 退出，错误提示只含用例号和失败原因。
- 如果响应不是可读取的 JSON、缺少 `choices[0].message.content`，或者正文为空或没有可用文字，命令会报 `用例 c01 的模型回复无法解析`，指明失败的用例和原因，以状态码 2 退出。这批回答只有全部处理成功后才会写入输出文件。
